# Chekino

Telegram-бот для двух участников: общая очередь фильмов и сериалов, независимые
оценки 1–5 и одна редактируемая карточка на каждый личный чат.
Задача: [первая версия #1](https://github.com/SuselMan/chekino/issues/1).

Python 3.12+, только стандартная библиотека. SQLite хранит каталог, оценки,
историю их исправлений, положение карточек, обработанные события и очередь доставки.
Отдельные контейнеры, npm и сервер базы не нужны.

## Настройка

Сначала создай приватный файл **за пределами репозитория**, например
`~/.config/chekino/config.json`, с правами `0600`; каталог — `0700`.
Все значения ниже — обозначения, не действительные секреты:

```json
{
  "token": "TELEGRAM_BOT_TOKEN",
  "users": [111111111, 222222222],
  "metadata_key": "KINOPOISK_API_KEY",
  "database": "/ABSOLUTE/PRIVATE/PATH/chekino.sqlite",
  "reveal_partner": false
}
```

`users` — ровно два разных **user ID**, полученных по доверенному приватному каналу.
Саморегистрации по `/start`, публичного pairing и разрешения доступа по username нет.
Бот обрабатывает только личный чат, где chat ID равен ID разрешённого пользователя.
Изменение состава участников существующей базы требует отдельной миграции.
`reveal_partner=false` — согласованное правило: оценка партнёра видна после своей.

```sh
python3 -m chekino --config ~/.config/chekino/config.json check-config
python3 -m chekino --config ~/.config/chekino/config.json run
```

Первая команда не обращается к сети. `run` начинает Telegram long polling;
автоматически webhook не снимает. Используй отдельного бота без другого poller
и активного webhook. Блокировка рядом с базой предотвращает второй poller Chekino.
Оба участника должны сами открыть личный чат с ботом и отправить `/start`.
Не передавай токен аргументом командной строки или через Git.

## Метаданные и рекомендации

Адаптер использует [Kinopoisk API Unofficial](https://kinopoiskapiunofficial.tech/):
нужен ключ после регистрации, заголовок `X-API-KEY`.
Проверена [актуальная OpenAPI-схема](https://kinopoiskapiunofficial.tech/documentation/api/openapi.json):
`GET /api/v2.2/films?keyword=…` и `GET /api/v2.2/films/{id}`.
Сайт сообщает лимит 500 запросов в сутки для новых пользователей; фактический тариф
и квоту ключа следует проверить в кабинете перед запуском. Платные услуги
автоматически не подключаются. Работа с действительным ключом проверена 22.10.2026: поиск, карточки и рекомендации.

Название всегда требует подтверждения кандидата с годом и типом, даже если поиск
вернул один результат. Неточные названия дополнительно уточняет Luna. Ссылка `https://www.kinopoisk.ru/film/ID/` или `/series/ID/`
добавляется после получения метаданных. Произвольные URL сервер не загружает.
Канонический числовой ID исключает дубли между ссылками и поиском.

`/new` подбирает фильмы отдельным агентом **GPT-6.1 Sol** через установленный
`codex exec` и текущую авторизацию Codex на VPS. Отдельный OpenAI API-ключ
не требуется. Запросы используют лимиты действующего аккаунта Codex.

Модель получает названия, годы и отдельные оценки A/B для просмотренных
произведений, а также список исключений. Telegram ID, имена, токены и
конфигурация в промпт не передаются. Отсутствующая оценка не считается низкой.
Подбор учитывает атмосферу, сюжет, юмор, режиссуру и отрицательные примеры;
порог рейтинга 7 и ограничение годом 1970 для AI-подбора убраны.

Агент предлагает до 30 произведений и по два коротких предложения о том,
почему фильм **может** понравиться вам обоим. Объяснение не раскрывает скрытые
оценки партнёра и не содержит спойлеров. Бот сверяет точное название, оригинал
и год через Кинопоиск; неоднозначные и не найденные произведения пропускаются.
Ссылки и постеры берутся только из проверенных метаданных.

Запас сохраняется в приватной `<database>.sol.sqlite`.
В фоне заранее готовятся **50 ещё не показанных полных карточек** с объяснениями,
постерами и метаданными. Пополнение включается, когда запас падает ниже 30,
и продолжается до цели 50; один вызов может дать запас немного выше цели.
Кинопоиск проверяется в фоновом worker, до показа, со своей SQLite-сессией кеша.
`/new` выдаёт **пять карточек с листанием** в одном сообщении, «Следующие 5» берёт
новую пачку. При первом заполнении первые пять доступны до завершения всего запаса.
При сбое агента уже готовый запас остаётся доступен; при редком недоборе
выдаются доступные проверенные варианты.

«Не интересно» сохраняет отдельный отказ участника. Это не просмотр и не оценка:
фильм не добавляется в каталог и не попадает второму в раздел оценок.
Отказ исключает фильм из рекомендаций обоим бессрочно. Sol получает отказы A/B
при следующей генерации как отрицательные примеры. Новые подборки предпочитаются
старым, но готовый запас не выбрасывается после каждого отказа/оценки.
Показы также бессрочны: показанные рекомендации не предлагаются заново.
Четыре ещё не открытые карточки пачки не считаются показанными, но зарезервированы
за текущим чатом и не выделяются одновременно другому.

Генерации ограничены 20 запусками за скользящие 24 часа, включая ошибки;
при сбоях есть пауза перед повтором. При холодном старте модель не выдумывает предпочтения.

Неточные названия и описания, которым нет точного совпадения в API, уточняет
отдельный агент **GPT-6 Luna**. Она получает только введённый запрос, без оценок.
До трёх вариантов проверяются через Кинопоиск и сразу показываются полными
карточками: постер/превью, описание, год, тип, ссылка. Между вариантами — стрелки.
Добавление требует нажатия «В очередь», даже если найден один вариант. Точные названия и ссылки идут напрямую в API.
Результаты уточнения кешируются; лимит — 60 запусков Luna за скользящие 24 часа.

Luna работает без дополнительного рассуждения, с сокращённым служебным контекстом.
Успешный поиск по оригинальному названию не повторяется по переводу.
При ожидании виден счётчик секунд (обновление каждые 5 секунд), затем отдельный
этап проверки в Кинопоиске. Проценты и обещанное время не выдумываются.

Оба агента работают в фоне: карточка показывает ожидание и обновляется сама,
очередь и команды остаются доступны. Ввод при уточнении не удаляется до
успешного результата. Смена раздела не заменяется позже завершившимся поиском.
Codex запускается без инструментов shell/web, с read-only sandbox,
`--ignore-user-config`, `--ephemeral` и структурированной схемой ответа.
Промпт идёт через stdin; stdout/stderr не попадают в Telegram или журнал.
Временных файлов с оценками нет. Приватный кеш содержит сгенерированные тексты.

## Кеш и квота API

Кеш **бессрочный**, сохраняется на диске рядом с базой:
`<database>.metadata.sqlite`. Лимит SQLite-файла — **1 ГиБ**, без резервирования
этого объёма заранее и без загрузки всего кеша в оперативную память.
При заполнении удаляются сначала наименее недавно использованные записи,
содержащие только просмотренные фильмы, затем остальные старые записи.
Чтение обновляет время использования. Для поиска с несколькими результатами
приоритет «просмотрено» применяется, когда просмотрены все произведения ответа.
SQLite FULL auto-vacuum возвращает освобождённое место файловой системе.
Временный журнал SQLite может кратковременно занимать дополнительное место.

Очередь, статус просмотра, оценки и их история лежат **отдельно**: удаление кеша
их не затрагивает. В основной базе остаются метаданные каталога и активных
карточек/результатов поиска; неиспользуемые временные кандидаты убираются.
Кеш содержит JSON API и ссылки на постеры, сами изображения бот не скачивает.
Бессрочный кеш означает, что исправления метаданных источником автоматически
не подхватываются; отдельное обновление по требованию пока не реализовано.

Предохранитель — не более **400 попыток обращения** к API за скользящие 24 часа,
включая неудачные запросы. Это оставляет запас относительно внешнего лимита 500.
Попадания в кеш не расходуют квоту и работают после исчерпания лимита.
Счётчик хранится отдельно от записей ответов в том же файле; очистка ответов
его не сбрасывает. Полное удаление файла сбрасывает и локальный счётчик,
поэтому не удаляй его для обхода ограничения. Пустые результаты тоже кешируются.

## Использование

- Название → выбор произведения → общая очередь; ссылка Кинопоиска → карточка.
- `/queue` — одна карточка с листанием; `/random` — случайный непросмотренный фильм.
- `/new` — пять вариантов с листанием, «В очередь», шкала 1–5, «Не интересно», «Следующие 5». До сохранения оценки/добавления каталог не меняется.
- `/rate` — просмотренные без **твоей** оценки; первая оценка исключает фильм
  из очереди и random у обоих. Оценка второго не заполняется автоматически.
- На карточке сразу видна шкала **1–5**. Нажатие сохраняет оценку; другое
  значение исправляет её. Текущая оценка отмечена галочкой.

Навигация каждого независима. Карточка содержит название, год, тип, описание,
Кинопоиск и запрашиваемое у Telegram крупное превью постера. Превью зависит от
Telegram и доступности изображения; его отображение нужно проверить в живом чате.
Свежий ввод удаляется только после обработки и успешного обновления карточек.
При ошибке поиска ввод остаётся, пояснение выводится в карточке. Старые сообщения
могут остаться из-за [ограничения deleteMessage в 48 часов](https://core.telegram.org/bots/api#deletemessage).
Ручное удаление карточки восстанавливается при следующем действии.

## Надёжность и ограничения

Данные, история оценки, дедупликация update/callback и необходимость перерисовки
записываются одной SQLite-транзакцией. Отправка в Telegram повторяется отдельно.
Устаревшая кнопка не может поставить оценку другому фильму: проверяются ревизия,
ID сообщения и текущая карточка. После изменения общего каталога старая кнопка
партнёра может потребовать повторного нажатия на обновлённой карточке.

Telegram не предоставляет ключ идемпотентности `sendMessage`: при аварии строго
между первой отправкой карточки и сохранением её ID возможна лишняя карточка.
Обычные действия используют `editMessageText`, не создавая подтверждений.
Результат редактирования «message is not modified» считается успешным;
новая карточка создаётся только при подтверждённом отсутствии прежней.
Дедупликация защищает локальные данные, но не обещает exactly-once доставку через сеть.

## Проверки

```sh
python3 -m unittest discover -s tests -v
```

Проверяются две истории оценок, первый просмотр, исправления, рекомендации,
неоднозначность, повтор событий, просроченные кнопки, запрет чужого доступа,
чистота чата, сбои доставки, перезапуск и SQLite backup/restore,
а также одновременная запись через два соединения.
Моки не заменяют живую проверку API и двух Telegram-чатов.

## Экспорт, резервная копия и восстановление

Команды создают **новый** приватный файл и отказываются перезаписывать существующий:

```sh
python3 -m chekino --config ~/.config/chekino/config.json backup /PRIVATE/BACKUP/chekino.sqlite
python3 -m chekino --config ~/.config/chekino/config.json export /PRIVATE/BACKUP/catalog.json
```

Backup использует SQLite Online Backup API: подходит и при работающем боте.
JSON содержит каталог, обе оценки, историю, отказы и показы рекомендаций; он тоже приватный. Для полного
восстановления используй SQLite-копию, а не JSON. Храни резервные копии зашифрованно
вне Git. Конфигурация с токеном копируется отдельно в защищённый бэкап.

Восстановление: останови **только Chekino**, сохрани прежнюю базу и её `-wal/-shm`
в приватном архиве, установи проверенную SQLite-копию по пути `database`, права
`0600`. Не смешивай восстановленную базу со старыми `-wal/-shm`; после архивации
убери их из рабочего пути. Проверь `PRAGMA integrity_check` и данные до запуска.
После длительного простоя Telegram мог удалить updates старше своего срока хранения;
резервная копия не восстанавливает пропущенные сообщения Telegram.

## Постоянный запуск

На VPS установлены `chekino.service` и `chekino-backup.timer`; исходники
интеграции и инструкция — `~/projects/vps-infra/docs/chekino.md`.
Приложение работает от suselman, данные приватные, входящие порты не открываются.
Перезапуск: `sudo systemctl restart chekino.service`.
Ежедневный бэкап содержит базу и конфигурацию, шифруется GPG AES256 в памяти;
на диск пишется только зашифрованный архив. Хранятся последние 14 копий.
Ключ: `~/.config/chekino/backup-key` (0600). Зашифрованный бэкап расшифрован,
целостность восстановленной SQLite проверена. Внешнее хранилище пока не настроено.
Ссылка бота добавлена в приватный реестр сервисов VPS.

Полная приёмка двух живых Telegram-чатов и визуальная проверка превью ещё нужны.
