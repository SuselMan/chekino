# Chekino: состояние реализации

Обновлено 22.10.2026 в сессии реализации задачи
[#1 — первая версия](https://github.com/SuselMan/chekino/issues/1).
Рабочая копия: `~/projects/chekino`, публичный репозиторий `SuselMan/chekino`.

## Реализовано локально

- Python 3.12 и SQLite без внешних зависимостей.
- Поиск названий с подтверждением года/типа; прямые ссылки Кинопоиска.
- Общий каталог без дублей, очередь, random, личная навигация и одна карточка на чат.
- Кнопка «📦 В архив» в очереди и «Ждут оценки»: общий бессрочный архив;
  «🗄️ Архив» и /archive — карточки с листанием и «↩️ Вернуть в очередь»;
  исключение из очереди, random, рекомендаций и повторного добавления.
  Поставленные оценки и их история сохраняются; архивирование не создаёт оценку
  другому участнику. При возврате фильм с оценкой возвращается в «Ждут оценки»
  для участника без оценки, непросмотренный — в очередь.
  Фильмы и метаданные сохраняются; архив включён в SQLite-бэкап и JSON-экспорт.
- Независимые оценки 1–5, просмотр при первой оценке, `/rate` для второго.
- Иконки на всех кнопках. В карточках — рейтинги Кинопоиска и IMDb /10,
  отсутствующие значения отмечены «—». Существующие записи дополнены из кеша
  без расхода API-запросов; внешние рейтинги отделены от личных оценок 1–5.
- Шкала 1–5 сразу в карточке, без промежуточной кнопки «Оценить»; выбранный
  балл отмечен галочкой. Исправление нажатием другого балла.
- Кнопка «Каталог» и раздел `/history` убраны по просьбе владельца; сохранённые
  фильмы и оценки не удаляются. Старые команды раздела возвращают в очередь.
- `/new`: непрерывное листание стрелками, добавление, оценка, «Не интересно».
  Счётчик учитывает весь готовый запас при открытии раздела и сохраняет
  знаменатель при подгрузке пятёрок, пока исходный запас не исчерпан.
  Вправо с последней карточки автоматически добавляются следующие из запаса;
  влево доступна история текущего раздела. Во время пополнения история сохраняется;
  уход назад отменяет автоматический переход после ожидания.
  Фоновый запас полных проверенных карточек: цель 50, пополнение ниже 30.
  Показы и отказы бессрочны; отказы не отмечают просмотр и передаются Sol как
  отдельная обратная связь A/B. Исключаются каталог, показы и отказы обоих. Подбор заменён
  агентом GPT-6.1 Sol на основе обеих историй оценок; к карточке два коротких
  предложения с объяснением. Пачки сохраняются в приватной .sol.sqlite.
- Неточные названия/описания уточняет фоновый агент GPT-6 Luna; проверка API
  и подтверждение пользователя обязательны. Ввод при ошибке не удаляется.
- У Luna видны прошедшие секунды и этап проверки Кинопоиска. После проверки
  сразу полная карточка; несколько кандидатов листаются. Убраны повторные
  запросы по переводу при найденном оригинале. Luna использует effort=none
  и project_doc_max_bytes=0; живая проверка опечатки — 4,38 с (один замер).
- Атомарная запись данных/дедупликации, повтор доставки карточек после сбоя,
  защита устаревших кнопок и чужого доступа. Локальная блокировка второго poller.
- SQLite online backup, JSON-экспорт, инструкции восстановления и приватной настройки.

## Проверено

Локальные автоматические проверки: `python3 -m unittest discover -s tests -v`.
Проверены сценарии двух участников, транзакционные повторы, одновременные записи
через два SQLite-соединения, восстановление backup и запрет посторонних.
В тестах Telegram и метаданные заменены заглушками; живой результат не заявляется.

Публичная OpenAPI-схема Kinopoisk API Unofficial прочитана 22.10.2026;
методы поиска и карточки существуют, нужен `X-API-KEY` после регистрации.
Источник и квота описаны в README. Действительный ключ не проверялся.

## Живая настройка и оставшаяся приёмка

Конфигурация `~/.config/chekino/config.json` (0600) настроена приватно:
отдельный токен, два ID из основного бота, ключ метаданных. В Git их нет.
`getMe`/`getWebhookInfo` успешны, webhook не установлен. Работает отдельная
`chekino.service`, автозапуск включён. После изменения кеша служба перезапущена;
Codex и остальные сервисы не перезапускались.

Метаданные проверены настоящим API: «Интерстеллар» — правильный ID/год,
описание и постер; «Дюна» — несколько произведений с типом и годом.
Рекомендации отфильтрованы до фильмов/сериалов, телешоу исключены.
Исправлена пагинация: диапазон берётся из totalPages источника; при исчерпании
первых выбранных страниц проверяются остальные. Раньше диапазон 1–10 мог
целиком попасть за реальные 5 страниц и ошибочно показывать пустую подборку.
Повтор поиска и повтор подборки с теми же параметрами: 0 сетевых вызовов.
Компактные отчёты в игнорируемом diagnostics/.

Кеш бессрочный (решение владельца 22.10.2026), максимум 1 ГиБ SQLite-файла,
watched-first LRU, место физически возвращается FULL auto-vacuum.
Счётчик 400 попыток за скользящие 24 часа сохраняется при перезапуске и очистке
ответов. Временные кандидаты в основной базе не накапливаются; каталог/оценки защищены.
Постеры кешируются как URL, их изображения получает Telegram.

Инфраструктура: `~/projects/vps-infra/docs/chekino.md`, служба и ежедневный
таймер зашифрованного бэкапа. Бэкап создан службой, расшифрован в памяти,
восстановленная SQLite имеет integrity_check=ok. Ключ отдельно вне Git.
Внешняя копия ещё не настроена. Карточка бота добавлена в приватный реестр сервисов.

Видимость оценки партнёра согласована: скрывать до собственной.
AI-подбор использует реальные оценки; гарантировать совпадение вкусов нельзя.
Агенты работают через установленный Codex с текущей авторизацией, без API-ключа
OpenAI. Sol реально создал подборку, один вариант проверен Кинопоиском.
Luna реально исправила «интерстелар» до «Интерстеллар», ID 258687 проверен API.
Новые вызовы не блокируют обработку Telegram; исходный ввод остаётся до результата.

**Осталось:** ручная приёмка обоих живых Telegram-чатов, визуальная проверка
превью, очистки ввода и кнопок. В рабочую базу тестовые фильмы/оценки не добавлялись;
сообщения от имени участников не имитировались. Issue #1 пока не закрывать.

## Отзывчивость кнопок

После жалобы на медленные оценки и листание проверены реальные запросы Telegram:
getMe 0,10–0,14 с, обновление текущей карточки 0,23 с. Исходная большая задержка
в момент проверки не воспроизвелась. Обработка листания на копии живой базы
в памяти: медиана 0,16 мс, максимум 0,27 мс (20 действий, без сети и записи
на диск). Для дальнейшей диагностики журнал службы
содержит длительности методов Telegram и обработки входящих действий, коды
ошибок и отклонения устаревших кнопок без идентификаторов и содержимого сообщений.

Проверка вариантов Luna и загрузка полных карточек перенесены в её фоновый поток
с собственной SQLite-связью кеша; раньше проверка могла блокировать основной цикл
на нескольких запросах метаданных. Подтверждение кнопки отправляется независимо в отдельном потоке,
карточка нажавшего обновляется первой. Сетевой таймаут обычных методов Telegram
сокращён с 40 до 8 секунд, подтверждения кнопок — до 2 секунд; long polling
был заменён короткими запросами (см. ниже).
Регрессионный тест удерживает запрос метаданных заблокированным и проверяет,
что оценка другого участника сохраняется и его карточка доставляется первой.
Всего 77 тестов проходят (включая общий архив и его восстановление из бэкапа).

По повторной жалобе на кубик журнал зафиксировал 8,239 с в answerCallbackQuery
и 0,140 с в editMessageText: карточка ждала подтверждения. Подтверждение вынесено
в отдельный однопоточный исполнитель с максимум одним незавершённым заданием:
сбой и очередь подтверждений не задерживают обработку и доставку карточек.
Регрессионный тест блокирует подтверждение и проверяет независимую доставку
карточки, отсутствие накопления заданий и безопасную обработку ошибки.
Изменение установлено; скорость в живом клиенте ещё требует проверки.

По жалобе на очередь в 21:20 журнал показал ещё одну причину: getUpdates
несколько раз занимал 40–42 с, после чего приходили пачки уже устаревших нажатий.
Обработка самих кнопок занимала 0,13–0,28 с. Долгое ожидание заменено коротким
опросом: Telegram timeout=1 с, сетевой таймаут 3 с, пауза 1 с при пустом ответе.
Обычный сетевой сбой опроса повторяется через 500 мс без общего backoff 3 с;
явный retry_after Telegram соблюдается. Offset остаётся в основной SQLite и
не продвигается на ошибке. Новые тесты проверяют оба таймаута, offset, восстановление
после ошибки и соблюдение retry_after. Скорость в клиенте требует живой проверки.

Дополнительная проверка соединений обнаружила нестабильность IPv6: из 30 TCP/TLS
подключений 2 не завершились за 500 мс; IPv4 — 30/30 успешных, максимум 103 мс.
Ожидание первой попытки соединения перед переходом к следующему адресу может объяснять
дополнительные задержки около сетевого таймаута даже при успешном ответе API.
Только Telegram-транспорт Chekino переведён на IPv4 через отдельный HTTPSConnection;
DNS остаётся штатным, TLS-сертификат и имя сервера проверяются стандартным HTTPS.
Настройки сети VPS и транспорт метаданных не менялись. Все IPv4-адреса из DNS
перебираются при ошибке с закрытием неудачного сокета. Реальные 10 getMe через
новый транспорт: без ошибок, 0,089–0,242 с. Короткий опрос сохранён. Отчёты замеров
лежат в игнорируемом diagnostics; токен и данные участников в них не записывались.

Telegram теперь повторно использует HTTPS-соединение, отдельно для основного
потока и подтверждений кнопок (thread-local). При обрыве сокет закрывается и
следующий вызов подключается заново; автоматического повтора отправок после
неопределённого результата нет. Таймаут сокета обновляется для каждого метода.
Проверка 10 последовательных getMe: первый 127 мс, остальные 30–32 мс, ошибок нет.
Регрессионный тест проверяет переиспользование, таймаут и восстановление после
разрыва. Версия установлена, итоговую задержку в клиенте нельзя вывести только
из серверного времени обработки.

После установки постоянного соединения реальные карточки доставлялись за
0,062–0,078 с (обработка кнопок целиком 0,066–0,085 с). Однако getUpdates всё ещё
периодически ждёт заголовков ответа до сетевого таймаута 3 с, в том числе на IPv4.
Поэтому проблему общей задержки нельзя считать полностью устранённой. Это
ограничение остаётся открытым отдельно от завершённых изменений архива/рейтингов.
Служба запущена; отдельного фонового процесса дальнейшей диагностики нет.

## Требования к Sol и исправление пополнения (23.10.2026)

Приватный TOML-файл по `requirements_file` перечитывается автоматически.
Свободный текст передаётся модели, год и страны дополнительно проверяются
по метаданным; версия требований отмечается в готовых карточках и подборках.
Смена требований исключает старые рекомендации из нового и уже открытого запаса.
Личные предпочтения в публичном репозитории не сохраняются. Файл входит
в зашифрованный инфраструктурный бэкап вместе с конфигурацией и основной базой.

Причина ночных повторов подтверждена: локальный бюджет метаданных 400/24 ч
был исчерпан. После этого сохранялись новые ответы Sol, но их проверка обрывалась;
последующие попытки снова запускали модель вместо продолжения сохранённого ответа.
Теперь бюджет проверяется до запуска Sol, ожидание берётся из времени освобождения
бюджета, частично проверенные ответы продолжаются без новой модели. Ошибки имеют
нарастающую паузу до часа. Нынешний лимит 20 запусков Sol не изменён и не сброшен; сообщение показывает
время ожидания вместо неверного «попробуй завтра».
Профиль содержит отдельные оценки обоих участников с равным весом; отсутствие
оценки не трактуется как отказ. При переносе правил существующие предложения
проверяются по кешу, не меняя каталог, оценки, архив или историю показов.

Проверки: 77 тестов, включая отказ от запуска модели при пустом бюджете,
возобновление частичного ответа без нового запуска, правки правил на лету,
фильтры года/стран и передачу требований в prompt. Живой новый запуск модели
при исчерпанном бюджете намеренно не выполняется.

## Ограничения

Превью запрашивается через Telegram `link_preview_options`; отображение зависит
от доступности постера и клиента, требует живой проверки. Пустые разделы — текст
в той же карточке. При сбое между первой отправкой и сохранением message ID
возможен дубль карточки: Telegram sendMessage не имеет ключа идемпотентности.
Ограничение удаления входящих старше 48 часов сохраняется.

## Публикация и ресурсы

Разрешения на push в текущем разговоре нет: изменения остаются локально.
Issue не закрывать до живой приёмки. Постоянное разрешение VPS-репозиториев
на Chekino не распространяется.
Временные тестовые базы удалены, зависимости и сборки не создавались.
Работают постоянные chekino.service и chekino-backup.timer. Приватные конфигурация,
ключ, основная база, кеш и зашифрованный бэкап сохранены вне Git. Неудачные
промежуточные архивы убраны; агент GPG отдельного homedir остановлен.
Сохранены компактные диагностические отчёты. Временных процессов не оставлено.

Оптимизация проверки: перед поиском используется индекс названий/года из
уже закешированных полных карточек (индекс хранит только небольшие ключи).
Известный фильм проверяется без API-запросов даже при другом переводе названия.
Страны из результата поиска проверяются до загрузки подробной карточки.
При локальном исчерпании бюджета другие позиции сохранённого ответа, уже
доступные в кеше, всё равно обрабатываются. Правила применены к существующему
запасу по кешу, личные оценки проверены до/после и не изменились.


## Диагностика доступности 11.11.2026

После сообщения о неработавших очереди и кубике вечером 10.11 проверены код,
служба и журнал. Ошибки Sol обрабатываются в background future; последнее
сохранённое начало генерации Sol — 22.10. Новых запусков модели в дни сбоя
не найдено. Служба активна с 30.10 без автоматических перезапусков. Связь
с лимитом Codex не подтверждена.

10.11 в 20:29:43 был разрыв idle-соединения подтверждения callback, затем
вызов редактирования карточки занял 0,144 с. Вокруг этого времени повторялись
таймауты получения обновлений. При изолированном замере 11.11 корректный
пустой ответ getUpdates(timeout=0) пришёл за 3,141 с, а следующий с timeout=1
за 1,036 с. Сетевой таймаут 3 с был слишком коротким и провоцировал разрывы.
Увеличен до минимум 10 с (либо запрошенное ожидание + 5 с), серверное ожидание
остаётся 1 с. Это запас на получение ответа, а не искусственная задержка кнопок.
Подтверждение callback повторяется один раз после транспортной ошибки; ошибки
400/429 не повторяются. Журнал обработанных кнопок теперь содержит имя действия
из белого списка без ID, аргументов, оценок и текста сообщений.

Добавлены проверки повторного подтверждения и работы очереди, стрелок, кубика
и сохранения оценки после отказа Sol. Исторический журнал не позволяет установить,
какое действие имело единственное обработанное нажатие 10.11; отсутствие других
записей не объясняет полностью доставку каждого нажатия пользователя.
Компактные отчёты: diagnostics/codex-limit-20261111.json и
 diagnostics/poll-timeout-20261111.json (вне Git). Новые запуски Codex для проверки
не выполняются; действия от имени участников не создаются.

Проверка 11.11: все 79 тестов прошли, включая сценарий отказа Sol с работающими
очередью/кубиком/оценкой. Исправление установлено перезапуском только Chekino;
Codex и портал не перезапускались. Личная база и конфигурация не редактировались.
