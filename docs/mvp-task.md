# Первая версия Chekino

## Цель

Реализовать первую версию Chekino — отдельного Telegram-бота для двух участников,
которые выбирают фильмы и сериалы для совместного просмотра. Каталог, очередь
и факт просмотра общие, оценки отдельные **1–5**. У каждого свой личный чат.

Рабочая копия на VPS: `~/projects/chekino`. Проект уже обнаруживается Codex-порталом:
`/new → chekino`. Перед работой прочитать `AGENTS.md`, `docs/product.md` и
`docs/project-state.md`. Здесь сформулирован итог обсуждения, не ранние предложения
о независимых очередях или пяти карточках на страницу.

## Команды и интерфейс

- `/queue` — одна **полная карточка** из общей непросмотренной очереди с листанием
  **⬅️ ➡️**, постером/превью, названием, годом, коротким описанием и Кинопоиском.
- `/new` — карточка новой рекомендации вне общего каталога с кнопками
  **«В очередь» · «Оценить» · «Ещё»**. Рекомендации для совместного просмотра.
- `/random` — случайный фильм из общей непросмотренной очереди.
- `/rate` — листаемые карточки просмотренных фильмов **без моей оценки**.
- На карточке очереди — **«⭐ Ждут оценки · N»**, переход к `/rate`.

Одна переиспользуемая карточка на личный чат: команды и кнопки меняют её содержимое,
а не создают бесконечные сообщения. Навигация каждого участника независима.
Не делать список только из названий, пять карточек на страницу или Mini App.

## Добавление, просмотр и оценки

1. Участник присылает название либо ссылку. Найти точное произведение и ссылку
   Кинопоиска. Для неоднозначного названия предложить выбор с годом и типом.
2. Добавленный фильм виден в общей очереди обоим. Повтор не создаёт дубль.
3. Сохранение первой оценки **1–5** означает «посмотрели оба» и убирает фильм
   из общей очереди и `/random`.
4. У второго фильм попадает в `/rate`: **«ПРОСМОТРЕНО — ждёт твоей оценки»**.
   Оценка первого не копируется второму. После второй оценки хранить обе.
5. Позволить исправить собственную оценку; не терять фильм и историю данных.

Из `/new`: «В очередь» добавляет фильм в общую очередь; «Оценить» даёт выставить
оценку непосредственно на этой карточке и сохраняет фильм сразу просмотренным;
«Ещё» заменяет рекомендацию без добавления. Само открытие выбора 1–5 не отмечает
просмотр. Учитывать конкурентные действия обоих, не плодить дублей.

## Чистота чата и Telegram

- Переиспользовать сообщение с карточкой, постером и inline-кнопками.
- Без отдельных штатных сообщений «добавлено», «оценено» и уведомлений о каждом действии.
- Свежие входящие сообщения/команды убирать после успешной обработки; при ошибке
  не терять ввод. Пустые разделы и ошибки навигации показывать понятно.
- Удалённую вручную карточку можно восстановить без потери данных.
- Не обещать очищать всю историю: обычный `deleteMessage` ограничен 48 часами.
  Документация: https://core.telegram.org/bots/api#deletemessage.

## Реализация и эксплуатация

- Выбрать простой самостоятельный стек и постоянное хранилище; обосновать выбор.
- Проверить доступный источник метаданных/постеров/рекомендаций и реальные условия API.
  Не выдумывать рейтинг/ссылку. Не оформлять платные услуги без согласования.
- Доступ только двум участникам с безопасной привязкой Telegram ID.
- Токен, Telegram ID, база, оценки, приватные логи — **вне Git и issue**.
  Репозиторий публичный. Токен ранее передан владельцем в приватной сессии,
  в файлах проекта не сохранён; получить его приватно при настройке.
- Перезапуск не теряет данные и не повторяет обработанные updates/callbacks.
- Документировать конфигурацию, запуск, экспорт/восстановление и резервное копирование.
- Интеграцию systemd/реестра сервисов оформлять в `SuselMan/vps-infra`.
  Не перезапускать `codex-server`, не трогать Grafetto, чужие стенды и домашнюю сеть.
- Перед публикацией проверить актуальное разрешение push Chekino; постоянное
  разрешение `vps-infra` и `codex-portal` не распространяется автоматически на него.

## Приёмка

- [ ] Ввод названия и ссылки приводит к правильной карточке; неоднозначность обработана.
- [ ] Добавление общее, дублей нет; карточки с превью и листанием работают в обоих чатах.
- [ ] Первая оценка убирает фильм из `/queue` и `/random` у обоих.
- [ ] Второй видит его в `/rate` и ставит независимую оценку 1–5.
- [ ] Все три кнопки `/new` работают, рекомендация исключает общий каталог.
- [ ] `/random` не выбирает просмотренное; пустые разделы обработаны.
- [ ] Штатные действия не накапливают сообщения; навигация участников независима.
- [ ] Перезапуск, повтор callback/update, одновременное добавление и оценка не портят данные.
- [ ] Проверены запрет чужого доступа, сохранность обеих оценок и восстановление базы.
- [ ] README и project-state описывают запуск, проверки и оставшиеся ограничения.

## Что уточнить по ходу

Видимость оценки партнёра до своей ещё не выбрана. Источник метаданных и начальные
предпочтения для рекомендаций нужно определить. Учёт сезонов, фильтры, отдельная
команда истории и «Посмотрели без оценки» не согласованы и не обязательны для MVP.

В этой сессии создаётся задача; реализацию продолжит отдельная сессия проекта.
